# ТЗ: бот-бухгалтер для цветочного магазина

Nov 6, 2026 · @KiriLL

## Резюме

Продукт — бот-бухгалтер в Telegram для цветочных магазинов: чат-бот для быстрых действий и отчётов плюс Mini App (приложение внутри Telegram) для ввода продаж, букетов, прихода и инвентаризации. Флорист вносит данные в течение смены, владелица сразу после закрытия получает отчёт, сверенный до тенге. Это не ИИ-агент: каждое действие идёт по фиксированному сценарию, каждая цифра считается по формуле из раздела «Формулы». Одна система обслуживает много владельцев, и каждый видит только свой магазин.

**Разработка идёт в два этапа.** Этап 1 — пилот у одного магазина на Google Таблицах и Apps Script за 0 ₸; в базе только имена, без телефонов. Этап 2 (отложен) — когда появятся платные клиенты, переезд на сервер в Казахстане: с 25 августа 2026 персональные данные должны храниться в РК. Структура, формулы и экраны на обоих этапах одинаковые.

| Решение | Выбор |
| --- | --- |
| Интерфейс | Чат-бот (смена, расходы, отчёты, тревоги) + Mini App (продажи, букеты, приход, брак, инвентаризация, каталог) |
| Этап 1: пилот | Google Таблица (база и панель владелицы) + Google Apps Script (бот и формулы) + страница Mini App на бесплатном хостинге. 0 ₸ в месяц |
| Этап 2: платные клиенты (отложен) | Один сервер в Казахстане: бот, сервер Mini App и база данных. От \~430 ₽ в месяц + домен раз в год. Google Таблица остаётся как выгрузка без телефонов |
| Клиенты | Одна система на всех. В каждой записи есть «Клиент» и «Точка», чужие данные не отдаются |
| Деньги | Только целые тенге, в базе — целые числа, никаких дробей. Округление — в одном месте, при расчёте процентов |
| Исправления | Записи не удаляются. Ошибку исправляет обратная запись, сделать её может только владелица |
| Чего бот не делает | Не заменяет онлайн-кассу (ККМ) и не выдаёт фискальные чеки; не считает налоги |

**Правило округления (одно на всю систему):** проценты округляются до целого тенге по математике — 0,5 и больше вверх, меньше 0,5 вниз. Пример: 1 048,5 → 1 049; 1 048,4 → 1 048. Проценты хранятся в сотых долях целым числом: 3% = 300, 2,5% = 250. Так компьютер считает без ошибок дробных чисел вроде 1 048,4999999.

## Архитектура и стоимость

Телеграм — только «окно» для ввода и отчётов; данные и расчёты живут на сервере. На этапе 1 «сервером» служат Google Apps Script и Google Таблица, на этапе 2 — сервер в Казахстане. Схема ниже показывает этап 1.

Любое действие в чате или Mini App проходит через один скрипт — именно там проверяется, кто пишет, и считаются все формулы. На этапе 2 правый блок переезжает на сервер в Казахстане, левая и средняя части не меняются.

| Часть | Этап 1: пилот (0 ₸) | Этап 2: платные клиенты (отложен) |
| --- | --- | --- |
| Чат-бот | Google Apps Script, вебхук Telegram | Python + aiogram на сервере в РК |
| Mini App | Веб-страница (HTML/JS + Telegram Web App SDK) на GitHub Pages | Та же страница на сервере в РК |
| Сервер для Mini App (API) | Веб-приложение Apps Script (doPost) | Python + FastAPI |
| База данных | Google Таблица: лист на каждый справочник и журнал | SQLite → PostgreSQL при 5+ клиентах |
| Панель владелицы | Экраны Mini App + просмотр таблицы (без права редактирования) | Экраны Mini App + выгрузка в Excel или Google Таблицу |
| Резервные копии | Ежедневная копия таблицы в Google Диск по расписанию | Ежедневная копия базы в другое хранилище в РК |
| Персональные данные | Только имена, без телефонов | Имена и телефоны — на сервере в РК |
| Когда переходим | — | Когда появятся платные клиенты, которым нужны телефоны покупателей, или когда копий таблицы станет больше 3 — до этого новые клиенты подключаются копией таблицы без телефонов |

**Требования к этапу 1 (Apps Script), без которых бот будет сбоить:**

- **Ответ Telegram без ошибки «302».** Вебхук должен отвечать через `HtmlService.createHtmlOutput()`, а не `ContentService`. После запуска проверить `getWebhookInfo`: нет ошибки и `pending_update_count` = 0.
- **Одна запись за раз.** Каждая операция идёт под блокировкой `LockService`, чтобы два флориста не списали последнюю розу одновременно.
- **Mini App шлёт запросы как простой текст** (`Content-Type: text/plain`). Иначе браузер заблокирует запрос к Apps Script.
- **Подпись Telegram проверяется в Apps Script** через `Utilities.computeHmacSha256Signature`.
- **Лимиты Apps Script** (6 минут на запуск, 30 одновременных запусков, 20 000 запросов к Telegram в сутки) для одного ларька с запасом. На несколько магазинов в пик 14 февраля или 8 марта их может не хватить — ещё одна причина для этапа 2.
- **Таблица защищена от ручной правки.** Владелица имеет право только на просмотр; пишет в таблицу только скрипт.

**Зачем потом нужен этап 2.** Серверы Google находятся не в Казахстане, а платным клиентам нужны телефоны должников и клиентов предзаказов. Штраф за незаконную обработку получит ваш клиент (от 60 МРП, 259 500 ₸ для малого бизнеса), а репутацию потеряете вы. Сервер в РК — от \~430 ₽ в месяц (цена Serverspace; точную цену и курс проверить перед покупкой) и окупается первой же подпиской. Переезд займёт несколько дней: листы таблицы переносятся в таблицы базы один к одному.

## Законодательство РК

Бот хранит персональные данные и работает рядом с кассой, поэтому его касаются два закона. Это не юридическая консультация: перед запуском продаж тексты согласий и договора стоит показать юристу.

### Персональные данные (Закон № 94-V)

| Требование | Что говорит закон | Как решаем в боте |
| --- | --- | --- |
| Хранение в РК | Ст. 12: с 25.08.2026 данные хранятся в базе и (или) цифровом объекте на территории РК (поправки Закона № 326-VIII) | Этап 1 (сейчас): Google Таблица, в ней только имена, без телефонов. Этап 2 (до первых платных клиентов): сервер и копии в РК |
| Согласие | Ст. 8: обработка — с согласия, которое можно подтвердить. В согласии указывается, передаются ли данные за рубеж | Флорист и владелица при первом входе нажимают «Согласен»; бот сохраняет дату, время и версию текста. На этапе 1 в тексте прямо сказано, что данные хранятся в Google и Telegram, то есть за рубежом |
| Данные клиентов магазина (должники, предзаказы) | Имя + телефон позволяют определить человека | Этап 1: только имя и короткая пометка («соседний магазин»), без телефона, ИИН и адреса. Телефон и отметка «Клиент согласен» появятся на этапе 2 |
| Удаление | По запросу человека — в течение одного рабочего дня | Владелица может обезличить должника или сотрудника: имя и телефон стираются, суммы в отчётах остаются |
| Штрафы | Ст. 79 КоАП, малый бизнес: незаконная обработка — 60 МРП (259 500 ₸); непринятие мер защиты — 300 МРП (1 297 500 ₸) | Защита — в разделе «Надёжность и безопасность» |

Оператором данных своих сотрудников и покупателей остаётся владелица магазина, а вы — поставщик сервиса, который хранит данные по её поручению. Это нужно закрепить в договоре.

### Онлайн-касса (Налоговый кодекс № 214-VIII, ст. 110)

- С 1 января 2026 онлайн-ККМ обязательна для расчётов наличными, картой и мобильными платежами, включая оплату по QR. Налоговый режим ИП от этого не освобождает.
- **Бот не является кассой и не заменяет фискальный чек.** Это управленческий учёт для владелицы. Фраза об этом — в договоре и в презентации.
- Для сверки в отчёте смены есть строка «Безнал для сверки». В будущем можно добавить сверку с суммами онлайн-кассы за смену.

## Журналы

Бот заполняет их сам. Каждая строка хранит дату и время (по Алматы), автора, смену, клиента, точку и **ID операции** — ниже эти поля не повторяются. ID операции создаётся в момент нажатия «Подтвердить». Если флорист нажал дважды или пропал интернет и запрос ушёл повторно, сервер увидит тот же ID и не запишет продажу второй раз.

| Журнал | Поля |
| --- | --- |
| Смены | № смены; флористы (1 или 2); время открытия и закрытия; наличные на начало (принято); расхождение при приёме; расчёт кассы; пересчёт; расхождение; остаток на следующую смену; статус (открыта / закрыта) |
| Чеки | № чека; тип (продажа / букет / предзаказ); цена флориста; скидка (₸ или %); скидка в ₸; итого; покупатель (для долга и предзаказа); статус (записывается / проведён / отменён); для предзаказа — дата выдачи и статус сборки |
| Оплаты | № чека (для погашения долга — покупатель); тип (оплата продажи / аванс / доплата предзаказа / погашение долга / возврат); способ (нал / безнал); сумма |
| Движение товара | тип (приход / продажа / брак / замена / корректировка / стартовый остаток); позиция; количество со знаком (+ или −); сумма закупки по строке (для прихода); поставщик или причина; № чека (для продажи и замены) |
| Касса | тип (доставка / аренда / прочее / ставка / процент / изъятие владелицей); сумма; кому (для ставки и процента); комментарий |

**Контрольные проверки при каждой записи:**

- Сумма оплат по чеку + долг + неоплаченный остаток предзаказа = итого чека. Иначе бот не сохраняет чек.
- Скидка не больше цены.
- Нельзя продать или списать больше, чем есть на складе. Бот предлагает сначала внести приход.
- Все суммы — целые числа; цена продажи, оплата, расход и изъятие — больше нуля, скидка — не меньше нуля.

## Кнопки флориста

В таблице указано, где живёт каждое действие: **в чате** (кнопки под сообщением) или **в Mini App** (форма с поиском и списками). Правило: всё, где больше одной позиции, — в Mini App; одна сумма или одно нажатие — в чате. Каждый сценарий заканчивается экраном «Проверьте и подтвердите», до подтверждения ничего не записывается. Без открытой смены доступна только кнопка «Открыть смену».

| Где | Действия |
| --- | --- |
| Чат | Открыть смену, расход из кассы, владелица забрала, погашение долга, отменить продажу, передать смену |
| Mini App | Продажа, букет, предзаказ, приход, брак, возврат, остатки, закрыть смену (инвентаризация + пересчёт кассы) |

| Кнопка | Шаги | Что записывается |
| --- | --- | --- |
| Открыть смену | Бот показывает остаток, оставленный прошлой сменой (в нём уже есть размен) → флорист пересчитывает и подтверждает или вводит другую сумму → второй флорист (если есть) | Смена. Если сумма отличается — разница записывается как «расхождение при приёме», владелице сразу приходит сообщение, касса считается от принятой суммы. В отчёте показываются позиции ниже минимума |
| Продажа | Позиции и количество → бот показывает сумму по каталогу → цена флориста (принять или ввести свою) → скидка (нет / ₸ / %) → оплата: нал, безнал, нал + безнал или в долг | Чек, оплаты, списание со склада |
| Букет | Состав: цветы, зелень и упаковка с количеством → цена всего букета → скидка → оплата (как в продаже) | Чек, оплаты, списание всех компонентов |
| Предзаказ | Клиент (имя, пометка) → дата выдачи → сумма заказа → скидка → аванс (нал / безнал / смешанный). Потом «Собрать» — состав со склада, и «Выдать» — доплата остатка | В день оформления: чек на полную сумму и аванс. При сборке: списание со склада. При выдаче: доплата |
| Приход | Позиция → количество → сумма по накладной за строку → следующая позиция → поставщик | Движение «+». Закупочная цена в каталоге обновляется. Касса не меняется — поставщику платит владелица |
| Брак | Позиция → количество → причина (пришло бракованным / завяло / сломано / другое) | Движение «−» |
| Возврат | Найти чек → вариант: вернуть деньги (сумма, нал / безнал) или заменить (состав нового букета со склада) | Деньги: оплата «возврат». Замена: движение «−» с типом «замена». Вернувшиеся завядшие цветы на склад **не** приходуют и повторно не списываются |
| Отменить продажу | Только чек текущей смены → причина | Чек «отменён»: товар возвращается на склад, оплаты и долг аннулируются, чек исключается из выручки для % |
| Погашение долга | Должник из списка → сумма (не больше долга) → нал / безнал | Оплата «погашение долга». В выручку для % **не** входит |
| Расход из кассы | Тип: доставка / аренда / прочее → сумма → комментарий | Касса «−» |
| Владелица забрала | Сумма. В течение смены — сразу, как владелица забрала; при закрытии — шагом после пересчёта | Касса «−», тип «изъятие». Владелице приходит уведомление |
| Передать смену | Для подмены в середине дня: проходит тот же сценарий, что «Закрыть смену», затем следующий флорист открывает свою | Две отдельные смены за день, у каждой своя касса и свой % |
| Остатки | Категория → список «позиция — количество» | Ничего, только просмотр |
| Закрыть смену | См. порядок ниже | Смена закрыта, отчёт владелице |

### Порядок закрытия смены

1. **Инвентаризация.** Бот показывает расчётный остаток по каждой позиции по категориям. Флорист нажимает «Верно» или вводит факт. Разница записывается как корректировка.
2. **Проверка расходов.** Бот спрашивает, все ли доставки, аренда и изъятия владелицы за день внесены.
3. **Пересчёт наличных вслепую.** Флорист вводит, сколько денег в кассе, не видя расчётной суммы.
4. **Расхождение.** Бот сравнивает пересчёт с расчётом и показывает разницу.
5. **Зарплата.** Бот считает ставку и % каждого флориста и пишет: «Возьмите из кассы: Анна — 6 049 ₸». Флорист подтверждает.
6. **Изъятие.** Если владелица забирает деньги сейчас, флорист вносит сумму. Бот подсказывает, сколько можно забрать, чтобы остался размен.
7. **Отчёт.** Бот считает остаток на следующую смену, закрывает смену и сразу отправляет отчёт владелице.

Если смена не закрыта, бот ждёт и сам её не закрывает. В 22:00 он присылает напоминание флористу и владелице. Новую смену нельзя открыть, пока не закрыта предыдущая.

### Правила интерфейса

- Кнопка подтверждения — системная главная кнопка Telegram внизу экрана с итоговой суммой («Провести 12 500 ₸»). После нажатия она блокируется до ответа сервера.
- Приложение берёт цвета из темы Telegram у флориста — светлой или тёмной.
- Крупные кнопки и цифровая клавиатура для сумм: флорист часто работает одной рукой.
- Без интернета продажа не проводится, и приложение прямо это пишет. Заполненная форма сохраняется на телефоне. Когда связь вернётся, флорист нажимает «Провести» ещё раз — запрос уходит с тем же ID операции, поэтому дубля не будет.

## Формулы

Все суммы — целые тенге. Функция «округлить» — до целого по математике (0,5 → вверх). Отменённые чеки нигде не учитываются.

### 1. Чек

```
Скидка в ₸ = сумма в ₸
            или округлить(Цена флориста × % скидки в сотых / 10 000)
            пример: 10% = 1 000 → 6 000 × 1 000 / 10 000 = 600
Итого = Цена флориста − Скидка в ₸

Проверка: Нал + Безнал + В долг + Остаток предзаказа = Итого
```

### 2. Выручка смены и зарплата

```
Выручка смены = сумма «Итого» всех чеков, оформленных в смену
                 (нал + безнал + в долг + предзаказы на полную сумму)

% флориста = округлить(Выручка смены × его % в сотых / (10 000 × N))
   где N = число флористов в смене (1 или 2)
   пример: 3% = 300, N = 2 → 69 900 × 300 / 20 000 = 1 048,5 → 1 049

ЗП флориста за смену = его Ставка + % флориста

Округление без дробей (для программиста):
   a = Выручка × p,   b = 10 000 × N
   результат = (2 × a + b) div (2 × b)    ← целочисленное деление, 0,5 вверх
   проверка: (2 × 20 970 000 + 20 000) div 40 000 = 1 049
```

Деление пополам и процент считаются одной формулой, округление один раз. Если сначала округлить половину выручки, а потом процент, результат может отличаться на 1 ₸. Погашения долгов и доплаты предзаказов в выручку смены не входят: процент с них уже начислен в день продажи.

### 3. Касса

```
Наличные на начало = сумма, принятая при открытии смены
   (обычно равна остатку, оставленному прошлой сменой; размен уже внутри)
Расхождение при приёме = Наличные на начало − Остаток прошлой смены

Расчёт кассы = Наличные на начало
  + все оплаты наличными за смену (продажи, авансы, доплаты, погашения долгов)
  − возвраты наличными
  − доставки − аренда − прочие расходы
  − изъятия владелицей в течение смены

Пересчёт = сколько флорист насчитал в кассе, не видя расчёта
Расхождение = Пересчёт − Расчёт кассы
   больше 0 — излишек, меньше 0 — недостача

После пересчёта из кассы выдаётся ЗП:
Можно забрать сверх размена = Пересчёт − ЗП всех флористов − Размен
Остаток на следующую смену = Пересчёт − ЗП всех флористов − Изъятие при закрытии

Безнал за смену = все оплаты безналом − возвраты безналом
   (сверяется с выпиской Kaspi)
```

Это та же формула флориста («продажи всего − терминал + остаток − зп, % − доставка − аренда»), только начинается она с реальных наличных. Иначе продажи в долг и неоплаченные предзаказы считались бы как наличные, которых в кассе нет.

**Пересчёт вслепую.** Флорист не видит расчётную сумму до пересчёта — иначе можно «подогнать» пересчёт под расчёт, и недостача не покажется. Зарплата и изъятие при закрытии списываются после пересчёта. Итог тот же, что у формулы флориста, но расхождение считается честно.

### 4. Склад (по каждой позиции)

```
Остаток = Стартовый остаток + Приход
        − Продано (штучно и в букетах, включая собранные предзаказы)
        − Брак − Замены по возвратам
        ± Корректировки по инвентаризации

Закупочная цена за шт = округлить(Сумма по строке прихода / Количество)
Стоимость брака, замен и недостач = Количество × последняя закупочная цена
```

### 5. Месяц

```
Выручка за месяц = сумма выручки всех смен
Деньги получены = нал + безнал за все смены − возвраты
Закупки = сумма всех строк прихода

Прибыль = Выручка − Возвраты деньгами − Закупки
        − ЗП − Доставки − Аренда − Прочие расходы
```

Брак, замены и недостачи товара из прибыли **не вычитаются**: эти цветы уже оплачены в закупках. Они показываются отдельно, чтобы видеть потери. Изъятия владелицы — это перемещение денег, а не расход, и в прибыль не входят.

## Пример расчёта смены

Расчёт проверен программой, все цифры сходятся до тенге. Данные условные. В смене два флориста, Анна и Мира: ставка у каждой 5 000 ₸, процент 3%. Наличные на начало — 15 000 ₸, из них 5 000 ₸ размен.

### Чеки смены

| Чек | Цена, ₸ | Скидка, ₸ | Итого, ₸ | Нал, ₸ | Безнал, ₸ | В долг / к доплате, ₸ |
| --- | --- | --- | --- | --- | --- | --- |
| 1. Букет: 7 роз, 3 эвкалипта, крафт | 15 000 | 0 | 15 000 | 15 000 | 0 | 0 |
| 2. 5 роз, скидка 10% | 6 000 | 600 | 5 400 | 0 | 5 400 | 0 |
| 3. Букет, смешанная оплата | 20 000 | 0 | 20 000 | 8 000 | 12 000 | 0 |
| 4. Игрушка в долг (Айгуль) | 4 500 | 0 | 4 500 | 0 | 0 | 4 500 |
| 5. Предзаказ, аванс | 25 000 | 0 | 25 000 | 0 | 10 000 | 15 000 |
| **Итого** |  | **600** | **69 900** | **23 000** | **27 400** | **19 500** |

Проверка: 23 000 + 27 400 + 19 500 = 69 900 — сходится.

Ещё за смену: погашен старый долг 3 000 ₸ наличными; возврат по вчерашнему чеку 2 000 ₸ наличными; доставка 2 500 ₸; аренда 4 000 ₸; владелица забрала 10 000 ₸.

### Зарплата

```
% каждой = округлить(69 900 × 3 / (100 × 2)) = округлить(1 048,5) = 1 049 ₸   (по D41 база процента = выручка − возвраты денег за смену; эталон с учётом D41 — docs/GOLDEN_TEST.md: 1 019 ₸)
ЗП Анны = 5 000 + 1 049 = 6 049 ₸
ЗП Миры = 5 000 + 1 049 = 6 049 ₸
ЗП всего = 12 098 ₸
```

### Касса

```
  15 000   наличные на начало (принято без расхождения)
+ 23 000   наличные по чекам смены
+  3 000   погашение долга
−  2 000   возврат
−  2 500   доставка
−  4 000   аренда
= 32 500   расчёт кассы

Пересчёт вслепую: 32 498 → расхождение −2 ₸ (недостача)

После пересчёта:
  32 498   в кассе
− 12 098   ЗП (Анна 6 049 + Мира 6 049)
           можно забрать сверх размена: 32 498 − 12 098 − 5 000 = 15 400
− 10 000   владелица забрала
= 10 400   остаток на следующую смену (в нём 5 000 размена)

Безнал для сверки с Kaspi: 27 400 ₸
```

### Склад: роза красная

```
40 на начало + 50 приход − 7 в букете − 5 штучно − 3 брак = 75 шт по расчёту
Инвентаризация: 74 → корректировка −1 шт (650 ₸ по закупке)
```

Предзаказ из чека 5 ещё не собран, поэтому его цветы со склада пока не списаны.

## Надёжность и безопасность

Деньги сходятся до тенге, только если ни одна запись не потерялась, не задвоилась и не пришла от чужого человека. Эти требования обязательны для версии 1.

| Риск | Защита |
| --- | --- |
| Чужой человек отправляет запросы напрямую на сервер | Каждый запрос из Mini App несёт подписанные данные Telegram (initData). Сервер проверяет подпись ключом бота (HMAC-SHA-256, ключ «WebAppData») и срок давности (auth\_date не старше 12 часов). Без проверки — отказ |
| Флорист одного магазина видит чужие данные | Клиент и точка берутся только из базы по проверенному Telegram ID, а не из запроса. Каждый запрос к базе фильтруется по клиенту |
| Двойное нажатие или повторный запрос | ID операции: сервер игнорирует повтор. Обновления Telegram с тем же номером (update\_id) тоже обрабатываются один раз |
| Два флориста продают последнюю розу одновременно | Операция идёт под блокировкой (на этапе 1 — LockService): проверка остатка, чек, оплаты и списание выполняются подряд, без чужих записей между ними. Вторая продажа получит отказ «нет на складе» |
| Сбой в середине записи | Google Таблицы не умеют записывать несколько листов «всё или ничего». Поэтому: строки операции пишутся с её ID, чек получает статус «проведён» последним, отчёты и остатки учитывают только проведённые операции. При повторе с тем же ID скрипт дописывает недостающее и проводит чек. На этапе 2 — настоящая транзакция базы |
| Неверная дата смены | Все даты и отчёты считаются по часовому поясу клиента (Asia/Almaty, UTC+5). Дата смены = дата её открытия, даже если закрыли после полуночи |
| Поломка сервера | Ежедневная резервная копия: на этапе 1 — копия таблицы в Google Диск по расписанию, на этапе 2 — копия базы в РК. Хранение 30 дней. Раз в месяц — пробное восстановление |
| Утечка ключей | Токен бота хранится в свойствах скрипта (Script Properties), не в коде и не на GitHub. Доступ к таблице — только у вас (редактор) и владелицы (просмотр); доступ по ссылке выключен |
| Уволенный флорист | Владелица отключает сотрудника — доступ пропадает сразу, его прошлые записи остаются |
| Утечка персональных данных | Сообщить в уполномоченный орган в течение одного рабочего дня. Все входы и действия пишутся в журнал, чтобы понять, что случилось |

**Автоматические тесты формул.** Пример из раздела «Пример расчёта смены» становится тестом: программа проводит эти чеки и проверяет, что расчёт кассы = 32 500 ₸, расхождение = −2 ₸, ЗП = 6 049 ₸ каждой, остаток на следующую смену = 10 400 ₸, безнал = 27 400 ₸, остаток роз = 75 шт. Тесты запускаются перед каждым обновлением — если хоть одна цифра разошлась, обновление не выкладывается.

| Вопрос | По умолчанию |
| --- | --- |
| Возврат денег уменьшает % флориста? | Нет: % уже выплачен в день продажи. Возврат виден в отчёте и вычитается из прибыли месяца |
| Аренда за день | Фиксированная сумма из настроек. Бот подставляет её при закрытии смены, флорист подтверждает |
| Аренда, если смен в день две (подмена) | Списывается один раз — в последней смене дня |
| Предзаказ без аванса | Это бронь: в выручку не входит и % не начисляется. Чек на полную сумму создаётся в день первой оплаты (как сказала флорист: предзаказ считается, когда его оплачивают) |
| Отмена предзаказа клиентом | Делает только владелица: возврат аванса или аванс остаётся магазину |
| Прибыль месяца | Считается от оформленной выручки, а закупки — по приходам. Если в конце месяца на склад завезли много цветов, прибыль этого месяца будет ниже, а следующего — выше. Для прозрачности в сводке есть стоимость остатка на начало и конец периода |
| Пересчёт кассы | Вслепую: флорист не видит расчётную сумму до ввода пересчёта |
| Напоминание о незакрытой смене | 22:00 |
| Продажа больше, чем есть на складе | Запрещена. Бот просит сначала внести приход |
| Новая позиция в каталоге | Флорист добавляет сам, владелица подтверждает позже (статус «На проверке») |
| Как долго действует вход в Mini App | 12 часов; потом приложение нужно переоткрыть из бота |
| Старт | Полная инвентаризация в день запуска через экран инвентаризации Mini App: остатки из тетради вносятся как «стартовый остаток», наличные — пересчётом. Неделю бот и тетрадь идут параллельно |

**Риск для владелицы, который стоит проговорить:** флорист получает процент с продаж в долг сразу. Если долг не вернут, владелица потеряет и товар, и этот процент. Контроль — строка «долги старше 30 дней» в месячной сводке.

## Рост: новые точки и новые клиенты

Структура: **Администратор → Клиенты (владельцы) → Точки → Флористы.** Поля «Клиент» и «Точка» есть в версии 1, поэтому рост не потребует переделки данных.

| Ситуация | Что добавляем |
| --- | --- |
| Вторая точка того же владельца | Общий каталог (цены можно задать по точке); отдельные склад, касса, смены и размен; кнопка «Перемещение» (минус на одной точке, плюс на другой); сводный отчёт по точкам и итого; флорист привязан к своей точке |
| Новый владелец | Свой клиент со своим каталогом, ставками, процентами и настройками. Данные клиентов не пересекаются. В договоре: данные принадлежат клиенту, при отказе — выгрузка и удаление |

| Масштаб | Технология |
| --- | --- |
| Пилот: один магазин (сейчас) | Google Таблица + Apps Script + Mini App на GitHub Pages, 0 ₸. Поля «Клиент», «Точка» и настройки клиента уже есть |
| Первые платные клиенты (отложено) | Переезд на сервер в РК, база SQLite. Один общий бот и одно Mini App на всех |
| 5+ клиентов | Тот же сервер, база PostgreSQL. Формулы, кнопки и экраны не меняются |
| Клиент хочет своё название | Отдельный бот с его именем и логотипом за доплату; код и Mini App — общие |
| Дальше | Сверка с онлайн-кассой, прогноз закупки к праздникам, другие ниши (кофейни, пекарни) |

**Задел для будущих клиентов уже в версии 1:** поля «Клиент» и «Точка» в каждой строке; все ставки, проценты, размен, аренда и категории — в настройках, а не в коде; сотрудники привязаны к точке; поле «Телефон» зарезервировано; листы таблицы повторяют будущие таблицы базы. Нового клиента на этапе 1 можно подключить копией таблицы и скрипта по шаблону.

Подключение новой точки или клиента: настройки и сотрудники → каталог → инвентаризация в день старта → неделя параллельно с тетрадью.
