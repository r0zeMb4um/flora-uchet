# Передача владелице и первый день

## Порядок запуска (коротко)
1. Вы: `resetTestData` с именем владелицы (убирает тестовых владельцев и флористов) → `inviteOwner` → ссылка владелице.
2. Вы: `installTriggers` (один раз), `health` в порядке.
3. Владелица: открывает по ссылке, «Открыть кассу», «Ещё» → «Настройки».
4. Владелица: «Ещё» → «Сотрудники» → «Добавить флориста», отправляет ссылку.
5. Флорист: открывает ссылку, соглашается, читает инструкцию в чате.
6. Владелица: «Склад» → «Добавить» (типовые, цены, остатки), **до первой смены**.
7. Флорист: «Открыть смену», продажи, вечером «Закрыть смену».
8. Вы: вечером отчёт пришёл? `health`, ошибок 0.

Для Кирилла (администратора). Порядок «до передачи» → «день передачи» → «первые дни».

## До передачи (делает администратор, ~15 минут)

1. **Чистые данные:** см. раздел «Убрать тестовые данные…» ниже (делается один раз вместе с передачей роли).
2. **Прогрев и автоматика.** `maintenance.gs` → `installTriggers` (один раз после любых обновлений, где добавлялись триггеры). В свойствах скрипта есть `ADMIN_TELEGRAM_ID`.
3. **Здоровье.** Открыть `…/exec?health=1` (адрес из `docs/LINKS.md`): `webhook.connected: true`, `errors_logged: 0`, `ops_not_posted: 0`, `stock_matches_journal: true`.
4. **Резервная копия.** В папке «Флора·Учёт — резервные копии» есть свежая копия (делается ночью сама).
5. **Закройте и откройте кассу** на своём телефоне: должна загрузиться последняя версия (в «Ещё» над вложенными экранами видна кнопка «Назад»).

## Убрать тестовые данные и подключить настоящую владелицу (одним заходом)

В таблице сейчас могут быть тестовые владельцы и флористы (после проверок приглашений). Чистим всё и сразу передаём роль:

1. Редактор скрипта → `admin.gs` → функция `resetTestData`. В строке `var OWNER_NAME = '';` впишите **настоящее имя владелицы**, например `'Айгуль'`.
2. Запустите с `CONFIRM = false`: в журнале будет список «Будет очищено» (в `staff` останется 1 владелица). Если цифры похожи на правду, поменяйте `CONFIRM` на `true`, сохраните, запустите ещё раз. Перед чисткой на Диск кладётся копия «ДО ЧИСТКИ» (оставьте её на неделю).
3. Запустите `inviteOwner`, в `NAME` впишите **то же имя**. В журнале появится ссылка `https://t.me/flora_uchet_bot?start=…` (одноразовая, 48 часов).
4. Отправьте ссылку владелице лично. Она нажимает, соглашается, нажимает «Открыть кассу».
5. Дальше флористов приглашает она сама («Ещё» → «Сотрудники» → «Добавить флориста»).

После этого в магазине один владелец (она), ни одного тестового сотрудника, а ваш Telegram больше не владелец: бот на ваши сообщения ответит «Нет доступа». Это нормально.

## Где вы, администратор, и как проверять

Отдельной «панели администратора» в кассе нет, это сделано специально (владелица не должна видеть вас внутри). Ваши инструменты:
- **Сообщения в чате с ботом:** копия каждого отчёта о смене (пока включён доступ админа, D16), ошибки бота («🛑 Ошибка бота») и недельный отчёт «всё спокойно / есть что проверить».
- **Здоровье:** `…/exec?health=1` (адрес в `docs/LINKS.md`).
- **Таблица Google:** листы `receipts`, `shifts`, `ops_log`, `audit` (ошибки). Руками не править.
- **Посмотреть кассу глазами:** `node scripts/stand.cjs` на вашем компьютере (копия с тестовыми данными, http://localhost:8766/?as=1 владелица, ?as=777 флорист). К боевым данным не подключается.
- **Свой экран владельца в боевой кассе** не нужен. Если когда-нибудь понадобится, можно временно пригласить себя владельцем второй раз (`inviteOwner` с другим именем), но владелица увидит вас в «Сотрудниках».

## День передачи: что делают владелица и флорист (в таком порядке)

Порядок важен: **склад вносится, пока нет открытой смены.**

1. **Владелица** → «Ещё» → «Настройки»: размен в кассе и время напоминания.
2. **Владелица** → «Ещё» → «Сотрудники» → «Добавить флориста»: имя, ставка за смену, процент (например 3 или 2,5). Появится ссылка: «Отправить в Telegram» флористу.
3. **Флорист** открывает ссылку, соглашается, нажимает «Открыть кассу».
4. **Владелица** → вкладка «Склад» → «Добавить»:
   - «Выбрать из типовых»: отметить, что есть в магазине;
   - в таблице у каждой позиции вписать **цену** (обязательно), **остаток** (по желанию, но лучше сразу), закупку можно не знать;
   - «Сохранить N позиций». Черновик не пропадёт, если закрыть кассу.
5. **Флорист** на «Главной» → «Открыть смену»: ввести наличные в кассе, выбрать «Только я» (или напарника). Первая смена магазина: сообщения о расхождении нет.
6. Дальше обычный день: продажи (плитки или «Букет»), «Склад» → «Принять товар» при поставке, «Ещё» для расходов, возвратов и т. д.
7. Закрытие: инвентаризация → расходы → пересчёт наличных вслепую → итог. Владелица получает отчёт в чат.

Если позиции нужно добавить, когда смена уже открыта:
- сохраните позицию **без остатка**, а штуки внесите приходом («Склад» → «Принять товар», нужна сумма по накладной);
- остатки при добавлении позиции вносятся только при закрытой смене (так «Склад» не расходится с пересчётом).

## Чего пока нет (сказать владелице честно)

- **Предзаказы и долги** на старте не ведём (решено, D33): кнопки есть, но для первых дней не нужны.
- **Закупочные цены** можно не вносить. Без них в отчёте брак и недостачи помечены «цена не указана», а прибыль считается без себестоимости. Цену закупки удобно внести после первых приходов.
- **Прибыль** пока считается просто: выручка минус зарплата, закупки, расходы и возвраты; расходы месяца (аренда и др.) целиком вычитаются из любого периода, поэтому в «Сводке» за 7 дней может быть большой минус. Это подписано на экране. Формулы вынесены на согласование с владелицей (см. `docs/AUDIT.md`).
- **Скорость:** Google отвечает около 2 секунд на каждое действие, первое открытие после паузы может занять 5–7 секунд. Это нормально для этапа 1.
- **Без интернета** продажи встают в очередь и уходят сами; всё остальное требует связи.

## Если что-то пошло не так

| Симптом | Что делать |
| --- | --- |
| Касса не открывается / пишет «Откройте кассу из бота» | Открывать кнопкой «Открыть кассу» в чате с ботом, а не по ссылке. Полностью закрыть и открыть заново. |
| Экран не обновился после правки | Закрыть кассу и открыть заново (Telegram держит старый файл до 10 минут). |
| «Нет доступа» | Человек не подключён: нужна ссылка-приглашение (владелица → «Сотрудники»). |
| Ссылка-приглашение «недействительна» | Одноразовая, 48 часов. Новая: «Сотрудники» → карточка флориста → новая ссылка. |
| Продажа в очереди «не проведена» | Нажать на полоску вверху: покажет причину. Ничего не потеряно, повтор не задвоит. |
| Цифры не сходятся | `…/exec?health=1`; лист `audit` (ошибки); не править ячейки вручную. Ошибочный чек в закрытой смене: `correctReceipt` (RUNBOOK). |
| Публикация Mini App не обновилась | GitHub → вкладка Actions → «Mini App на GitHub Pages» → «Re-run». Либо пустой коммит в `main`. |
| Нужно проверить интерфейс без телефона | `node scripts/stand.cjs` → http://localhost:8766/?as=1 (владелица), `?as=777` (флорист). Для чистого магазина `--clean`. |

## Что смотреть в первую неделю

- Каждый вечер: пришёл ли отчёт о смене владелице, сошлась ли касса.
- Раз в день: `health` (ошибок 0, `stock_matches_journal: true`).
- Записывать, что искали дольше всего и что хотелось убрать или переименовать.
- После недели: решить вопросы из `docs/AUDIT.md` (прибыль по себестоимости, аренда по дням, отмена предзаказа в выручке).
