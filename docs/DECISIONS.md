# Решения по проекту (дополнение к ТЗ)

Здесь записано то, чего нет в `docs/TZ.md` или что уточняет его. **При расхождении с ТЗ действует этот файл.** Когда решение перенесено в живое ТЗ (claude.ai), отметьте это в колонке «В ТЗ».

Статусы: **принято** — решил владелец проекта; **по умолчанию** — заложено разработкой, подтвердить с владелицей магазина на пилоте (меняется настройкой или небольшой правкой).

| № | Вопрос | Решение | Статус | В ТЗ |
| --- | --- | --- | --- | --- |
| D1 | Язык этапа 2 | **Node.js** вместо Python. Ядро расчётов и логика операций переезжают на сервер без переписывания; эталонный тест тот же | принято | нет |
| D2 | Остатки склада | Журнал `stock_moves` — источник правды. Текущие остатки хранятся в листе `stock_balance` и обновляются в той же блокировке, что и операция. Ночью скрипт сверяет `stock_balance` с журналом и пишет администратору, если разошлось | принято | нет |
| D3 | Ставка и % при смене настроек | При открытии смены ставка и % каждого флориста фиксируются в листе `shift_staff`. Зарплата смены считается только по этим значениям. Изменения в `staff` действуют со следующей смены | принято | нет |
| D4 | Долги: учёт и старт | Все долги — в одном журнале `debt_moves`: стартовый долг из тетради (+), продажа в долг (+), остаток предзаказа при выдаче (+), погашение (−), отмена чека (−). Долг покупателя = сумма его строк. Стартовые долги в выручку и % не входят | по умолчанию | нет |
| D5 | Бронь без аванса | Хранится в листе `reservations` (покупатель, дата выдачи, сумма). В выручку не входит. При первой оплате бронь превращается в чек-предзаказ в текущей смене — выручка и % в этот день, как в ТЗ | по умолчанию | нет |
| D6 | Чек на 0 ₸ (скидка = цене) | Запрещён: итого чека > 0. Подарок оформляется как списание с причиной «подарок» (тип движения `defect`, причина `gift`), в отчёте видна его стоимость по закупке | по умолчанию | нет |
| D7 | Исправление чека в закрытой смене | Пересчитываются выручка, % и отчёт смены (пометка «исправлено»). Наличные факты смены (пересчёт, выданная ЗП, изъятие, остаток на следующую смену) не меняются. Разница по ЗП показывается владелице строкой «к доплате / к удержанию». Доплата выдаётся из кассы в следующей смене флориста (касса, тип `pay_adjust`); удержание бот только показывает, решает владелица | по умолчанию | нет |
| D8 | «Записи не удаляются» и статусы | Факты (деньги, товар, касса, долги) — только новые строки. Состояния (статусы чека, сборки, смены, брони, приглашения; остатки в `stock_balance`; цены, ставки и прочие поля справочников) обновляются на месте, но каждое изменение — отдельная операция в `ops_log` и строка в `audit` | принято | нет |
| D9 | Состав пилота | Пилот: все действия флориста + отчёты владелице в чате + просмотр таблицы. Экраны владелицы в Mini App (Сегодня, история, сводка, каталог, сотрудники) — после пилота. Исправления на пилоте делает администратор функцией скрипта по просьбе владелицы | по умолчанию | нет |
| D10 | Визуал | Переработка дизайна — отдельная задача (см. `docs/BACKLOG.md`). До неё Mini App верстается по текущим макетам и токенам | принято | — |
| D11 | Аренда за день | При закрытии смены бот подставляет аренду из настроек, если за этот день на точке её ещё не вносили; флорист подтверждает или убирает. При «Передать смену» бот спрашивает «Будет ещё смена сегодня?» — если да, аренду не подставляет (её внесёт последняя смена дня). Вручную аренду можно внести и в течение смены | по умолчанию | нет |
| D12 | Выдача предзаказа без полной доплаты | При выдаче остаток к доплате платится полностью (нал / безнал / смешанно) или, по явному выбору флориста, оформляется в долг покупателя (`debt_moves`, тип `pickup`). Выдать с «висящим» остатком нельзя | по умолчанию | нет |
| D13 | Предел возврата денег | Сумма всех возвратов по чеку не больше суммы, реально оплаченной по этому чеку. Возврат по чеку в долг — это уменьшение долга, а не выдача денег | по умолчанию | нет |
| D14 | Зависшие операции | Операция в статусе `pending` дольше 1 часа (флорист не нажал повторно) ночью переводится в `failed`: её строки нигде не учитываются, остатки пересчитываются по журналу, администратору приходит сообщение | принято | нет |
| D15 | Публичный репозиторий | Бесплатный GitHub Pages требует открытый репозиторий, поэтому код проекта публичный. В репозитории никогда нет токенов, ключей, ID таблиц и реальных данных — только код, документы и тестовые данные | принято | нет |
