# Инструкция администратора

Всё, что делается руками в редакторе скрипта: https://script.google.com/ → проект «Флора·Учёт — пилот» (аккаунт flora.uchet.kz@gmail.com).
Функцию запускают так: открыть файл слева → выбрать функцию в списке рядом с «Выполнить» → «Выполнить» → смотреть «Журнал выполнения».

## Выкладка новой версии
На компьютере в папке проекта:
```
npm run deploy
git push
```
`npm run deploy` — тесты → код в Google → то же развёртывание (адрес не меняется) → проверка бота. `git push` — касса публикуется на GitHub Pages через минуту.

## Свойства скрипта (⚙️ «Настройки проекта» → «Свойства скрипта»)
| Свойство | Что | Кто ставит |
| --- | --- | --- |
| `BOT_TOKEN` | токен бота от @BotFather | администратор, руками |
| `ADMIN_TELEGRAM_ID` | ваш Telegram ID (`/id` в боте) — сюда приходят ошибки, ночные проверки, копии отчётов (D16) | администратор, руками |
| `SPREADSHEET_ID`, `WEBHOOK_KEY`, `BOT_USERNAME`, `LAST_UPDATE_ID`, `REMINDED_*` | служебные | скрипт сам |

## Один раз после установки
1. `setup` (файл setup.gs) — листы, тестовый магазин.
2. `BOT_TOKEN`, `ADMIN_TELEGRAM_ID` — в свойства.
3. `connectBot` (connect.gs) — вебхук, кнопка «Касса», ссылки-приглашения.
4. `installTriggers` (maintenance.gs) — напоминание 22:00, ночная проверка и копия 03:00, проверка бота 09:00. Google попросит разрешение на Диск (для копий) — разрешить.

## Автоматика (после installTriggers)
| Когда | Что | Куда пишет |
| --- | --- | --- |
| каждые 15 минут | смена открыта после времени напоминания точки (по умолчанию 22:00) → флористам смены и владелице, раз в день | Telegram |
| 03:00 | зависшие операции → «не прошла» (D14); сверка остатков с журналом; копия таблицы в папку «Флора·Учёт — резервные копии», старше 30 дней — в корзину; заполненность таблицы | администратору — только если есть проблемы |
| 09:00 | вебхук Telegram, очередь, ошибки за сутки | администратору — только если есть проблемы |

## Если бот молчит
1. В браузере: `https://script.google.com/macros/s/<DEPLOYMENT_ID>/exec?health=1` (ID — в `apps-script/config.js`). Должно быть `"webhook":{"connected":true,"pending":0,"error":""}`.
2. `connected: false` или ошибка → запустить `connectBot`.
3. `errors_logged` > 0 → лист `audit`, строки `error`: там текст ошибки.
4. Google просит авторизацию (после изменения прав скрипта) → запустить любую функцию в редакторе и разрешить.

## Восстановление из копии (пробовать раз в месяц)
1. Google Диск → папка «Флора·Учёт — резервные копии» → нужная копия → «Открыть».
2. Проверка без переключения: убедиться, что в копии есть листы `ops_log`, `shifts`, `receipts` и последние смены на месте.
3. Настоящее восстановление (только если основная таблица испорчена):
   - в свойствах скрипта заменить `SPREADSHEET_ID` на ID копии (из адреса: `/spreadsheets/d/<ID>/edit`);
   - ⚠️ привязка редактора к старой таблице останется — работать с копией через свойство безопасно, скрипт пишет туда, куда указывает `SPREADSHEET_ID`;
   - открыть `…/exec?health=1` — `setup: true`, `stock_matches_journal: true`;
   - всё, что проведено после времени копии, потеряно — сверить с тетрадью и внести заново.

## Сотрудники и владелица
- Флористов добавляет владелица в чате: «Сотрудники» → «+ Добавить флориста».
- Владелицу — только администратор: функция `inviteOwner` (admin.gs), вписать имя, ссылка в журнале (48 часов).

## Исправить чек в закрытой смене (D26)
Функция `correctReceipt` (admin.gs): вписать номер смены и чека, сначала `CONFIRM = false` (показать чек), потом `true`. Владелице придёт пересчитанный отчёт с пометкой «ИСПРАВЛЕНО».

## Обезличить покупателя по просьбе (закон о ПД, в течение рабочего дня)
Функция `anonymizeCustomer` (admin.gs): вписать имя. Имя стирается, долг и суммы остаются.

## Сменить токен бота (если утёк)
1. @BotFather → `/revoke` → выбрать бота → новый токен.
2. Свойство `BOT_TOKEN` — заменить.
3. `connectBot`.

## Новый магазин (этап 1)
Копия таблицы и скрипта по шаблону: создать новую таблицу, `clasp create` в новой папке с тем же кодом, `setup`, свойства, `connectBot`, `installTriggers`. Данные клиентов не пересекаются. При 3+ копиях — переход на этап 2 (ТЗ).
