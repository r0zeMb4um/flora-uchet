# Флора·Учёт — бот-бухгалтер для цветочного магазина

## Кто работает с тобой
Владелец проекта — Кирилл. Он новичок в программировании (опыта с кодом нет).
- Общайся по-русски, простым языком, без жаргона; новые термины объясняй одной фразой.
- Работай маленькими шагами: один шаг → показать результат → следующий.
- Перед командой, которая что-то устанавливает, удаляет или меняет вне папки проекта, объясни, что она делает, и спроси разрешения.
- Когда нужно действие Кирилла (создать бота в BotFather, нажать «Развернуть» в Apps Script, открыть ссылку), давай пошаговую инструкцию с точными названиями кнопок.

## Что строим
Telegram-бот + Mini App для управленческого учёта цветочного ларька: продажи, букеты, предзаказы, приход, брак, возвраты, долги, касса смены, зарплата флористов, отчёты владелице.
Это НЕ ИИ-агент: каждое действие — фиксированный сценарий, каждая цифра — по формуле из ТЗ.

**Источник истины — `docs/TZ.md` + `docs/DECISIONS.md`** (при расхождении действует DECISIONS). Если код и документы расходятся или чего-то нет — остановись и спроси Кирилла, не придумывай правило сам.

## Стек (этап 1, сейчас)
- База и панель владелицы: **Google Таблица** (лист на каждый справочник и журнал, см. `docs/DATA_MODEL.md`).
- Логика и бот: **Google Apps Script** (V8). Код хранится локально в `apps-script/` и выгружается командой `clasp push`.
- Mini App: статическая страница **HTML + JS + Telegram Web App SDK** в `miniapp/`, хостинг **GitHub Pages**.
- Три слоя (см. `docs/ARCHITECTURE.md`): ядро `apps-script/core/` (формулы и логика операций, без Google API, тестируется в Node `node --test`) → адаптеры (листы, Telegram, Mini App API) → интерфейс `miniapp/`. Ядро не вызывает адаптеры.
- Файлы ядра без `import/export`: глобальные функции + `if (typeof module !== 'undefined') module.exports = {...}` — один файл работает в Apps Script, Node и браузере.
- Этап 2 (сервер в Казахстане, **Node.js** — решение D1) ОТЛОЖЕН. Не начинай его без прямой просьбы.

## Жёсткие правила (нарушение = ошибка в деньгах)
1. **Деньги — только целые тенге.** Никаких float в суммах. Проценты хранятся в сотых долях целым числом: 3% = `300`.
2. **Округление одно, «0,5 вверх», целочисленно:** `round(a / b) = Math.floor((2*a + b) / (2*b))` для неотрицательных a, b.
   - % флориста = `round(revenue * pct_bp / (10000 * N))`, N — число флористов в смене (1 или 2). Делить пополам и брать процент — ОДНОЙ формулой.
   - Скидка в % = `round(price * discount_bp / 10000)`.
3. **Записи не удаляются и не редактируются.** Ошибку исправляет обратная запись (только владелица).
4. **Идемпотентность:** каждая операция из Mini App несёт `op_id` (UUID, создаётся на телефоне при нажатии «Провести»). Повтор с тем же `op_id` не создаёт дублей — скрипт дописывает недостающее и отвечает «уже проведено». Telegram `update_id` тоже обрабатывается один раз.
5. **Блокировка:** любая запись идёт под `LockService.getScriptLock()`; проверка остатка и запись — внутри одной блокировки.
6. **Проведение:** строки операции пишутся с её `op_id`, а в `ops_log` статус `posted` ставится ПОСЛЕДНИМ. Отчёты и остатки учитывают только операции со статусом `posted`.
7. **Касса — пересчёт вслепую:** флорист не видит расчётную сумму до ввода пересчёта. Зарплата и изъятие при закрытии — после пересчёта.
8. **Нельзя продать или списать больше остатка.**
9. **Часовой пояс — `Asia/Almaty` (UTC+5).** Дата смены = дата открытия.
10. **Персональные данные (этап 1):** только имена и короткая пометка у покупателей. Телефоны НЕ хранить (поле есть, но пустое).
11. **Секреты:** токен бота и прочие ключи — только в Script Properties. Никогда в коде, в git или в чате.
12. **Telegram:** вебхук отвечает через `HtmlService.createHtmlOutput()` (иначе ошибка 302). Mini App шлёт запросы с `Content-Type: text/plain`. Каждый запрос Mini App проверяет `initData` (HMAC-SHA-256, ключ `WebAppData`, `auth_date` не старше 12 часов) через `Utilities.computeHmacSha256Signature`.
13. **Клиент и точка** берутся из таблицы `staff` по проверенному Telegram ID, никогда из тела запроса.
14. **Один `doPost`** на бота и Mini App. Вебхук проверяется ключом в адресе (`?k=` = `WEBHOOK_KEY` из Script Properties), весь обработчик Telegram в `try/catch` и всегда отвечает 200; повторы отсекаются по `LAST_UPDATE_ID`.
15. **Развёртывание одно и то же:** `clasp deploy -i <DEPLOYMENT_ID>`, только через `npm run deploy`. Новое развёртывание меняет адрес и ломает бота и Mini App.
16. **Остатки** читаются из `stock_balance`, который обновляется в той же блокировке, что и операция. ЗП смены — только по `shift_staff`. Итого чека > 0.
17. **Внутри блокировки — никаких запросов к Telegram**: уведомления отправляются после снятия блокировки.

## Тесты
- Перед каждой выкладкой (`clasp push`, публикация Mini App) запускай тесты расчётов: эталонная смена из `tests/golden_shift.json` должна дать ровно те цифры, что в `docs/GOLDEN_TEST.md`. Хоть одна цифра разошлась — не выкладывать.
- Новое правило в формулах = новый тест.

## Как работать
1. Перед большим шагом — короткий план (3–7 пунктов) и вопрос «делаем?».
2. Делай по `docs/PLAN.md` по порядку, отмечай выполненное в нём галочками.
3. После шага — скажи простыми словами, что сделано и как Кириллу это проверить.
4. Git: коммить после каждого рабочего шага с понятным сообщением на русском.
